# Sera Composer V0.1

> 这是可复现实验基线。当前产品闭环已升级到 [Sera Composer V0.2](SERA_COMPOSER_V02.md)，但 V0.1 文档保留用于比较与消融实验。

Sera Composer V0.1 是建立在现有安全乐谱编辑基线之上的“理论驱动创作层”。它不让通用 LLM 直接重写 MusicXML，也不声称替代专业作曲家或专用音乐生成模型。它把创作拆成可检查的高层计划、确定性音符实现、多候选评审和现有 ScorePatch 事务四个阶段。

明确的旋律创作意图也可以从普通“修改提案”入口进入。诸如“重写旋律”“主题变奏”“重新和声化”等指令会被确定性意图路由器转交给 Composer；原子编辑器不会再用“不支持生成新旋律”拒绝它们。路由只改变规划方式，不放宽最终 ScorePatch：仍然只能改动选区内已有事件的精确音高，并保持节奏、事件数量、配器与宿主版式。

## 当前可用能力

- `theory_variation`：在宿主选区内重新设计音高，保留所有节奏、事件数量、配器和排版。
- `reharmonize`：重新设计和声及伴奏音高；当计划要求保留旋律且选区包含左手时，右手保持不变。
- `orchestration_advice`：输出音域、密度、加倍和角色分配方案，但不在 V0.1 中直接增删声部或替换乐器。
- 每次处理 1–8 个小节，最多返回 4 个候选，界面默认返回 3 个。
- 实时 LLM 可提出风格、和声、织体、动机、张力和力度计划；具体 event ID 与音高始终由服务器决定。
- 未配置 API 时使用同一套确定性理论规划和候选评审，不会伪装成 LLM 结果。

## 使用方法

1. 在 MuseScore 中打开乐谱并选择 1–8 个小节。
2. 通过 Sera Score Bridge 将乐谱与选区发送到 Sera。
3. 在 Sera 中切换到“创作草案”。
4. 输入目标，例如：“把当前选区改写成有清晰终止的浪漫主义钢琴段落，保留节奏和配器”。
5. 检查 CompositionPlan、和声路径、候选评分与理论依据。
6. 点击“选择此候选并审查”。此时仍未修改宿主乐谱。
7. 在最终 ScorePatch 审查中确认保护范围、修改数量和验证状态，再应用并生成宿主修订。
8. 返回 MuseScore，打开最新 reviewed revision。

## 创新点与可检验假设

本项目不以“LLM 能作曲”作为创新主张，而聚焦以下系统创新：

1. **Theory-to-Patch 可追溯链**：每个计划与确定性检查都关联稳定的理论 claim ID，能够追溯“为什么这样规划”和“为什么通过或拒绝”。
2. **宿主骨架内的受约束创作**：创作不是整谱再生成，而是在专业记谱软件的既有节奏、事件、配器和版面骨架内重新组织音高与和声。
3. **生成与批评分离**：通用 LLM 只提出高层计划；服务器生成多个候选，再由保护范围、MusicXML 往返、和弦骨干、终止、声部进行和可演奏性批评器排序。
4. **创作与编辑共享安全边界**：候选不是旁路结果，而是标准 ScorePatch，继续使用源指纹、目标/保护范围、事务回滚、预览和宿主源文件保留式导出。
5. **无需专用音乐模型的可验证基线**：理论知识与确定性搜索提供可复现基线；LLM 的增益可以在同一管线中单独测量，而不是与执行安全混为一体。

对应的研究假设是：与一次性整谱重写或一次性 patch 相比，“高层理论计划 + 多候选确定性实现 + 分层批评 + ScorePatch 事务”能提高非目标内容保护率、结构有效性和可解释拒绝率。音乐审美质量仍需要独立的人类评审，不能由当前规则分数替代。

## 知识来源边界

`sera_edit/composer/theory_knowledge.py` 保存的是项目原创的简短工程规则摘要，不存储或复述受版权保护书籍的长段内容。后续可以建立合法来源的检索库，但检索内容必须带来源、适用风格和版本；理论原则只能影响高层计划与评审，不能绕过宿主安全约束。

## 确定性评审

每个候选至少检查：

- 事务与 MusicXML 往返是否有效；
- 是否只修改目标范围内的音高；
- 是否保留节奏、事件数量、配器和版面；
- 强拍和弦骨干音比例；
- 结尾是否落到主音；
- 是否存在大于八度的跳进、音域越界或声部交叉；
- 风格配置下的平行五/八度与声部进行评分。

总分用于候选排序，不是“作品质量”的普遍量表。任何硬安全检查失败的候选都不能进入应用流程。

## API

`POST /sera-edit/composer/preview`

```json
{
  "score_document": {},
  "brief": "重新设计浪漫主义和声，保留右手旋律",
  "target_scope": {"measures": [1, 2], "staffs": [1, 2]},
  "protected_scope": {"staffs": [1]},
  "candidate_count": 3,
  "seed": 42
}
```

响应包含 `plan`、`theory_context`、`planner`、`candidates`、`selected_candidate_id` 与 `baseline_guarantees`。端点只做预览，不提交乐谱状态。

## V0.1 限制

- 直接应用只支持音高重写；结构性配器、增删音符、改变时值、拍号或乐器仍然 fail closed。
- 罗马数字和声与音域规则是透明基线，不覆盖所有调式、爵士和非西方传统。
- 当前“理论分数”主要是工程代理指标；不得把它当作审美、原创性或专业作曲水平的自动证明。
- 后续应加入人工盲评、风格分层 benchmark、理论检索来源审计，以及宿主可逆结构编辑协议。
